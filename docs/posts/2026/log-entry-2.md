*This is part of a series where I document building my own docs site from scratch as I go from tech writer to docs engineer, building AI-assisted documentation pipelines.*

Today was about giving my *Engineer the docs project* an identity: building a logo, choosing a color palette, and selecting fonts.

This is not the part where I claim to be a designer. I'm not. But I do enjoy this type of work and spending an unreasonable number of hours looking at colors and fonts just to find the “right look and feel” (spoiler: I never find it and I keep constantly changing my mind).

The site needs to signal a few things before anyone reads a word: technical credibility, clarity, and enough warmth that a technical writer considering the jump into documentation engineering doesn't feel they have wandered into a beige enterprise maze.

I chose a palette built around deep navy, teal, and orange: structured enough for the engineering side of the project; clear and energetic enough that it doesn't look like a generic corporate documentation site.

For the logo, I grabbed inspiration from Daniel Procida's presentation [“Always complete, never finished”](https://youtu.be/Wc7n7uIg4AM?si=rtw0cFqn8qemMHKz), where he compares documentation to a plant. Like plants, documentation should always be complete, but is never finished. It's an evolving product.

As a former plant biologist, this metaphor had me at “plant.”

So, I used Figma to stitch this idea with a terminal window and a gear: documentation as a living thing, supported by the systems that keep it useful.

And, ta-da: habemus logo.
